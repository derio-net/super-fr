### p4-cli-scaffold-is-the-constraint · discovery · Scaffolding through the real CLI is the whole test; the cwd is what makes it work (phase 4)

The phase's single load-bearing constraint is that the plan be built by 'fr plan create --phases-file' rather than by writing 01.yaml. Two mechanical facts made that awkward enough to be worth recording. (1) plan_cmd.create_cmd resolves its repo root from Path.cwd(), NOT from VK_REPO_ROOT -- the env var the module's _fr helper sets and every other test in the file relies on. The test therefore has to monkeypatch.chdir(root) before invoking create, and takes a monkeypatch fixture for that reason alone; without it the plan is scaffolded into the real repo. (2) plan-review is a kind: cli step that executes the real 'fr plan self-review' against the scaffolded plan, so the fixture plan must actually pass self-review: phase 1 carries skeleton: true, tasks are single-step (refactor-exempt), and fr_version is floored at >=4.2.0,<5.0.0. Phase 2's missing tier does trip phase 2's new untiered-agentic-phase warning, which is warn-level and leaves the exit code at 0 -- that warning firing inside this test is expected and is itself a small confirmation that phase 2's probe reaches a CLI-scaffolded plan.
