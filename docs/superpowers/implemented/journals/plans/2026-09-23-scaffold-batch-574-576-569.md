### p6-live-env · discovery · live-proof environment: colima does not mount /private/tmp; the bash guard admits only literal 'cd <repo> && fr isolation …' into a foreign fr-enabled repo (phase 6)

1. **colima does not mount /private/tmp.** The first container ups ran from the session scratchpad (`/private/tmp/...`). Each build succeeded and then `docker run` failed:
   `docker: Error response from daemon: invalid mount config for type "bind": bind source path does not exist: /private/tmp/.../scratchpad/live/gl-demo/.git`
   The same happened for jvm-demo and gt-demo. fr bind-mounts the MAIN repo's common `.git` dir, and colima (`mounts: []`, so only its default of `$HOME`) cannot see `/private/tmp`. This is an environment limit, not a defect in the branch. The demo repos were moved to `~/.cache/fr-live-demos/` and re-run there. hw-demo (worktree mode, no docker) stayed in the scratchpad.
2. **The bash guard admits a foreign fr-enabled repo only through the literal `cd <repo> && fr isolation …` form.** Once a demo repo had a devcontainer profile, it counted as fr-enabled. `cd <demo> && uv run --project <worktree> fr isolation up …` was then refused with:
   ``fr-isolation: `<demo>` is not an fr isolation workspace (no valid `.fr-isolation` marker), so a live pipeline elsewhere does not open it for general work — reaching another repo is for entering ITS isolation, not for running anything there. Do: `cd <demo> && fr isolation up --branch <branch>` (allowed from here; …), then run the command from the worktree it reports. See plugins/super-fr/rules/fr-isolation-required.md (#421).``
   The guard was not bypassed. `up` and `down` used that literal form, which runs the globally installed fr 4.17.1. `exec` used this branch's fr, run from inside each demo worktree, which the guard admits. The #574/#576 behaviour under test comes from this branch's fr either way: the scaffold output and the toolchain inside the container. #569's full lifecycle used hw-demo, which has no profile and so is not fr-enabled, and it ran entirely on this branch's fr.
