# Retirement addendum — 2026-05-14

Phase 1 of this plan was implemented and merged as PR #128 on 2026-05-14
(commit `07fabf1`, restoring `vk issue create` as v2.0.5 → 2.1.3 after
the subsequent rebase chain). Phase 2 (`vk issue convert`) was never
dispatched.

After a v1-retirement audit on 2026-05-14, **Phase 1 was reverted** and
this plan is being closed for good. Reasons:

- `vk issue create` had no callers in any `skills/`, `rules/`, or other
  `src/` module — it was a CLI surface with no v2 workflow invoking it.
- v2's canonical follow-on Issue path is brainstorm → spec → plan →
  `vk apply`. Agents file plans, not standalone Issues; `vk apply` emits
  bridge-compatible Issue bodies via `src/vk/render.py`.
- For genuine one-off Issues, raw `gh issue create --label vk-ready`
  with an ~11-line bridge contract template is a trivial workaround.

See the retirement decision spec:
`docs/superpowers/specs/2026-05-14-v1-command-retirement-finalized-design.md`.

History remains intact: Issue #85 (Phase 1 tracking Issue) is closed;
PR #128 is merged; the revert PR is the source of truth for the final
state. Phase 1's `tracking_issue` stamp and `completion.at` marker stay
on `01.yaml` as the historical record of what was attempted.
