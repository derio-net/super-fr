# fr triage: show open PRs with CI and merge status

- **Date:** 2026-09-22
- **Status:** designed
- **Origin:** gh#558
- **Goal:** `fr triage` shows open PRs — including issue-less ones anchored to a spec or debug journal — with CI and merge badges.

## 1. Problem

`fr triage` collects PRs only to attach them to issues. `collect.py` runs one
`gh pr list --state all` per repo and `invert()` maps PR → issue using
`closingIssuesReferences`. Two things are lost:

1. A PR that closes no issue is dropped. fr-goal and fr-debugging PRs often
   land without an issue, so they never appear on the board. On 2026-09-22,
   super-fr had 5 open PRs like this. None of them would render.
2. CI and merge state are not collected. A linked PR renders as `PR #n · open`.
   Nothing shows red checks, a conflict, or a branch behind main.

## 2. Goal

An operator running `fr triage` on any harness sees every open PR: linked PRs
as badges on their issue row, issue-less PRs as their own rows in a PRs
section, each with CI and merge state, and each judged against an intent
anchor. Non-goals: code review (stays with `/code-review`), other forges
(`Forge` protocol seam unchanged, one new method at most), writing to the
forge.

## 3. Design

### A. Collect: one extra bulk call per repo, open PRs only

```
gh pr list --state open --json number,title,isDraft,url,headRefName,closingIssuesReferences,files,statusCheckRollup,mergeable,mergeStateStatus,reviewDecision
```

Do not add these fields to the existing `--state all` call. `statusCheckRollup`
is an expensive GraphQL field; requesting it for up to 1,000 closed PRs risks
timeouts. Reduce at collect time: store a summary on `PullRequest`, not the raw
check list: `checks: {pass, fail, pending}`, `mergeable`, `merge_state`,
`review`. Add top-level `Facts.prs` for open PRs closing no in-scope issue.
Linked PRs stay as tags on their issue row only (Q&A 2).

Anchor bodies (below) are fetched only when the PR's `files` actually contains
a spec or debug-journal path, one `gh api repos/O/R/contents/<path>?ref=<head>`
per anchored PR, capped at 2,000 chars like issue bodies. Skip on forge error
and record as unanchored (Q&A 1).

### B. Intent anchors (deterministic, from `files`)

First of these that exists:

1. a closing issue (`closingIssuesReferences`, in scope);
2. a spec: `docs/superpowers/specs/*.md` (plus `journals/specs/`, and the
   `spec:` ref in `plans/*/_meta.yaml`) among the PR's changed files;
3. a debug journal: `docs/superpowers/journals/debug/*.md` among changed files;
4. none → `unanchored`, itself a finding.

Spec/journal lives on the PR's branch, so read at the head ref. Checked
2026-09-22: all 5 issue-less super-fr PRs carry an anchor (4 specs, 1 debug
journal).

### C. Judgements for PRs

Key grammar already fits (`<repo>#<n>`, issues and PRs share one number
sequence). Reuse the existing `issues` map, adding optional
`delivery: delivers | partial | drift | unanchored` plus reason (Q&A 3).
Tier comes from the anchor, not the diff: anchor issue's tier if judged,
else tier the spec Background / journal symptom by failure cost. Delivery is
deliberately shallow (diff vs anchor), not a code review.

### D. Render

- CI + merge badge on every PR tag: ✓ / ✗ / ● for checks, plus
  `CLEAN` / `BEHIND` / `DIRTY` / `BLOCKED`. Show `mergeable: UNKNOWN` as
  unknown (lazily computed; never guess). Show `collected_at` near badges
  (CI goes stale in minutes).
- PRs section first with unranked issues: anchor, delivery verdict, badges.
- Filter chips for red CI and conflicts.
- `check` gains unranked PRs. SKILL.md update (PR half of loop, anchor order,
  delivery verdicts) in the same PR, then both `scripts/sync-opencode.py` and
  `scripts/sync-hermes.py`.

### E. Stages unchanged

Stages (`stage.py`, spec §3.E) describe lifecycle. CI is a badge, not a stage
(`pr-failing` would mix minute-stale state into a vocabulary `check` depends
on).

### F. Housekeeping

- `facts.json` schema 1 → 2. Cache state regenerated by `collect`, not a
  registered artifact kind: no migration. Error says "re-run collect".
- Tests with captured `gh` JSON fixtures (checks mixed, UNKNOWN mergeable,
  no-anchor PR, cross-repo closing ref).
- Acceptance-matrix rows for the new surface. Minor version bump.

## 4. Risks

- `statusCheckRollup` cost: open-only call bounds it; closed history untouched.
- `UNKNOWN` mergeable flaps: displayed verbatim, never interpreted.
- Anchor path drift (`specs/` vs `journals/specs/` vs `_meta.yaml` ref): engine
  matches all three; unknown layouts fall to `unanchored` loudly.
- Extra per-PR anchor fetches (N open PRs): only for PRs whose `files` already
  matched, so typically single digits.

## 5. Test Plan

**In this PR:**

1. Unit collect: open-PR call fields passed; checks summarised; UNKNOWN kept;
   issue-less PR lands in `Facts.prs`; linked PR does not duplicate.
2. Unit anchors: spec path, journal path, `_meta.yaml` spec ref, none →
   unanchored; anchor body capped at 2,000 chars; forge error → unanchored.
3. Unit judgements: PR key shares grammar; delivery values validated; tier
   inheritance from anchor issue.
4. Unit check: unranked PRs reported; issue sets unchanged; exit 0 always.
5. Unit render: badges, UNKNOWN text, `collected_at`, PRs section first,
   filter chips; deterministic bytes.
6. Schema 1 refused with "re-run collect" message.
7. Skill validation + neutrality + both mirror tripwires green.
8. Acceptance rows added; `fr acceptance check` green.

**Post-merge, operator-driven:**

9. On Claude Code + OpenCode: `fr triage collect --repo derio-net/super-fr`,
   judge an issue-less PR, render and open the board.
10. Hermes: not walked (`not-implemented` with reason).
