### p1-hazard-shadows-orphan-worktree-remove · discovery · The new guard shadows the pre-existing stray-worktree-remove-failure test (phase 1)

test_down_raises_when_worktree_remove_fails (pre-existing) uses _orphan_worktree(...,
keep_dir=True): shutil.rmtree the worktree, `git worktree prune`, then re-mkdir an EMPTY
directory at the same path. That directory is no longer a git repository at all (its
gitdir was pruned away), so `git status --porcelain` run there now fails (not a git
repo) -> _reap_hazard classifies it kind="unverifiable" and ReapRefused fires BEFORE
_teardown_container / `git worktree remove` are ever reached -- exactly the "one
enforcement site" ordering the spec specifies (§3.1).

This is a genuine, deliberate behavior change from phase 1, not a bug: the #354
invariant ("a failed query is not evidence of absence") now applies uniformly, including
to this stray-directory edge case. Fixed by:
- changing the original test to force=True (still exercises the worktree-remove
  post-condition failure this test is about, since force skips the new guard);
- adding test_down_reap_hazard_guard_precedes_worktree_remove_failure, which asserts the
  new precedence directly under force=False (ReapRefused, kind="unverifiable").

Also fixed a genuine regression the same change caused: _reap_hazard now short-circuits
to None (no hazard) when state.worktree does not exist on disk at all -- otherwise
test_down_raises_when_worktree_remove_fails / test_down_completes_when_worktree_already_gone
(the keep_dir=False variant) crashed with FileNotFoundError from subprocess (cwd does not
exist), since `git status --porcelain` was being run with a cwd that was removed
out-of-band. A worktree that is already gone has nothing left to query and nothing left
to lose.

Relevant for phase 2/3: any content-guard or dry-run code that also calls
`_reap_hazard`/queries the worktree should keep this same "worktree missing => no
hazard, not unverifiable" short-circuit, or it will reproduce the same crash on gc's
orphan-worktree classification path.
