### disc-dogfood · discovery · The bug reproduced on this plan's own scaffolding — live evidence, not a fixture

This plan was scaffolded by the very command it fixes. The phases file declared a tier on all five phases (standard/standard/standard/hard/standard). After 'fr plan create --phases-file' at fr 4.8.0: 01.yaml kept skeleton AND acceptance and lost tier; 02-05.yaml kept acceptance and lost tier. Zero tier keys across five phases, exit 0, no warning. ### p1-f1 · finding [fixed] · Byte-stability — an explicit spec goal — had no test at all (phase 1)

The spec's stated contract is 'emitted only when set so pre-tier plans stay byte-stable', and the plan step said to confirm it. Nothing pinned it: grep found no assertion anywhere that a phases file WITHOUT tier produces a header with no tier key. The skeleton precedent (test_plan_acceptance_links.py:186) does exactly this for its own field, so the omission was asymmetric as well as untested. Fixed class-wide rather than for tier alone: the derived test now scaffolds TWO phases — one carrying every optional field, one carrying none — and asserts the bare phase omits every field not in _ALWAYS_EMITTED. A future optional field emitted unconditionally now fails this test. Verified the assertion has teeth by mutation: changing 'if ps.tier is not None' to emit unconditionally makes it fail at line 155, and it passes again on revert.

### p1-f2 · finding [fixed] · The derived test gave phase 1 depends_on: [1] — a self-dependency (phase 1)

_REPRESENTATIVE_VALUES put every optional field on a single phase numbered 1, including depends_on: [1]. That is phase 1 depending on itself, which violates the plan model's backward-only rule (phase N may only reference phases < N) and is caught by self-review's cycle check, not by create(). It passed only because create() does not validate dependencies — and it sits in precisely the function phase 1 just created, _preflight_phase_error, which is where a cycle check would naturally be added. The day someone adds one, this test breaks with a message about cycles in a test about field coverage. Fixed by moving the optional fields onto phase 2, where depends_on: [1] is valid and actually meaningful.
