### v2-glab-contents-broken-live · finding [open] · GitLab adapter fails live: contents API omits the mandatory ref parameter

First live exercise of RealGlabClient against a self-hosted GitLab instance (host, group and project redacted per .claude/rules/third-party-privacy.md; default branch master). Results: list_dir works; the issues endpoint is reachable; file_exists and read_file are BROKEN. GitLab's GET /projects/:id/repository/files/:path requires a ref query parameter -- without it the API returns HTTP 400 {'error':'ref is missing, ref is empty'}. real_glabclient.py sends none. Severity is asymmetric: read_file raises loudly, but file_exists swallows every GlabError into False under its documented fail-soft posture, so a malformed request is indistinguishable from an absent file. That is why the unit suite never caught it -- the tests mock _run_glab, so the missing parameter never reaches an API. Verified fix: ?ref=HEAD works and is branch-agnostic (the project's default branch is master, not main). Two further gaps found in the same pass: _run_glab never passes --hostname and GITLAB_HOST appears nowhere in the repo, so there is no documented way to target a self-hosted instance; and _hosts.DEFAULT_HOST_BACKENDS covers only github.com/gitlab.com, so a self-hosted GitLab host resolves to 'github' unless .devcontainer/fr-profiles.yaml declares backend: gitlab. Blocks the coda's GitLab claim until fixed.

### v2-no-binaries-in-repo · decision · No binaries in super-fr: casts, video and stills live outside the repo entirely

Operator constraint, two independent reasons. Privacy is the lesser one. The load-bearing reason is that super-fr IS a Skill -- it is cloned onto every consumer's machine via the marketplace rsync -- so committed binaries inflate every install forever and can never be removed from history. Decision: casts, rendered video and stills live OUTSIDE the repo (not merely gitignored), reached through an asset manifest of paths plus checksums. NOTE a pre-existing violation this exposes: docs/presentation/version-1/diagrams/ already holds 17 committed PNGs. They predate this rule and are now inherited weight in every clone. Flag for the operator: v2 must not add to it, and removing the existing ones is a separate decision since it needs history rewriting to actually reclaim the bytes.
