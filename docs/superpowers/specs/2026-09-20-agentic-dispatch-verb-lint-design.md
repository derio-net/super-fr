# Agentic dispatch-verb lint — catching work assigned to an actor that cannot perform it

**Status:** Draft
**Date:** 2026-09-20
**Issue:** super-fr#428
**Sibling:** #420/#422 (poisoned dispatch going *in*); this is the capability assumed going *out*.
**Out of scope:** #496 (the run cursor offering a `tag: manual` phase to a subagent) — owned by the parallel `fr run` cursor run. #428 item 3 (`fr journal check --require-reviews`) — see §3, decision d1.

## 1. Goal

A plan step can tell `fr-phase-executor` to dispatch a subagent. The executor
has no tool that can do it. It does the nearest thing it can, reports the
deviation honestly — **and ticks the step anyway**. The plan then records
completion for work nobody performed as written.

Close that at **authoring time** with an error-severity `fr plan self-review`
lint, and at **execution time** with an executor contract that refuses the
tick. Both are prevention; neither is a hook, because there is no tool call to
intercept.

## 2. Background — what exists today (verified 2026-09-20, in-repo)

### 2.A The executor is a leaf on both harnesses

```yaml
# plugins/super-fr/agents/fr-phase-executor.md
tools: Read, Edit, Write, Bash, Grep, Glob        # no Agent
```

```yaml
# .opencode/agent/fr-phase-executor-hard.md (generated by scripts/sync-opencode.py)
permission:
  edit: allow
  bash: allow
  task: deny                                       # OpenCode's dispatch tool
```

The absence is **structural and harness-independent**: Claude Code omits
`Agent` from the frontmatter grant, OpenCode denies `task`. A tool grant is
fixed by frontmatter, so the executor can never dispatch anything, on any
harness.

### 2.B Why #422's PreToolUse hook is structurally blind to this

`fr-phase-executor-guard.sh` (#422) intercepts an `Agent|Task` **call** —
correct for #420, where the poisoned dispatch is a call that happens. Here no
tool call is ever made: the executor reads an instruction it cannot satisfy and
substitutes the nearest thing it can. A PreToolUse hook has nothing to fire on.

### 2.C The rule this mirrors already exists, and its comment states the policy

`fr.plan_ops.self_review` carries the agentic-purity gate (#252) — two
error-severity detectors per agentic phase: a deferred (`'-'`) step whose note
defers forward, and manual-operation language in a not-yet-ticked step
(`_MANUAL_VERB_RES`). Its comment is the precedent this spec follows:

> Deliberately conservative (precision over recall) — the deferred-step lint
> above is the load-bearing detector; this one catches the authoring mistake
> before any deferral happens.

Identical shape: **work assigned to an actor that cannot perform it.** #252
catches human-only work in an agentic phase; this catches orchestrator-only
work.

### 2.D Measured: #428's literal pattern list is unusable in this repo

Run during the brainstorm over every agentic step of every plan folder in this
repo that a modern `fr` can still read — `docs/superpowers/plans/` plus
`docs/superpowers/implemented/plans/`. The corpus is **43 plan folders /
1,419 agentic steps**, and the shortfall against the 105 entries on disk is
itself worth stating: 38 archived plans carry an `fr_version: '>=3.0.0,<4.0.0'`
pin and are rejected outright by `fr` 4.8.0 (frozen artifacts, never migrated —
`.claude/rules/artifact-versioning.md` §"What this rule does not cover"), 3 more
fail `PhaseDoc` validation, and 21 entries are not folders at all. The 43 that
parse are every live plan plus every archived plan written since the 4.x line:

| Pattern, as #428 proposes it | Hits | Verdict |
|---|---|---|
| `\bdispatch(es\|ed\|ing)?\b` | **237** (16.7% of steps) | all false positives |
| bare `<word>:<word>` token | 42 | `start:end`, `cli:app`, `fr:synced` |
| `\bspawn\b` | several | "prompt agents spawned…" prose |
| `subagent_type` | 2 | steps *implementing* OpenCode dispatch |
| `Task tool` | 1 | "the dispatch tool" |
| `delegate to` | 1 | Python delegation |
| `use the <X> agent` | **0** | clean |

super-fr is a repo *about* dispatch — "GREEN: implement `fr_dispatch.tick()`",
"assert `fr apply --yes` refuses to dispatch an unreachable plan". At error
severity the literal list would fail `fr plan self-review` on super-fr's own
plans, i.e. the gate would be turned off within a week of shipping.

The narrowed shape in §4.A scored **0 hits on those same 1,419 steps** while
matching the observed real defect verbatim.

### 2.E The observed defect (derio-net/frank, 2026-07-28, per #428)

Four steps read ``Dispatch `blog-craft:post-researcher` per post``. That agent
is normally dispatched by the `/blog-post` skill, which runs in the main loop
where `Agent` exists. Routed through `fr-phase-executor`, the researcher never
ran once: the executor read the agent's definition file and followed the
protocol *inline*, inside the context holding the phase brief and the
orchestrator's framing — the very context the agent exists to be blind to. The
work looked complete and the step was ticked.

## 3. Operator decisions (batched Q&A, 2026-09-20)

Recorded in `docs/superpowers/journals/specs/2026-09-20-agentic-dispatch-verb-lint.md`.

- **d1-scope** — ship #428 items **1, 2 and 4**. Item 3
  (`fr journal check --require-reviews`) is a new CLI surface and stays open as
  its own issue. Rationale: a gate that errors without saying what to write
  instead is half a fix, so the executor contract (2) and the fr-plan guidance
  (4) are what make the lint (1) actionable.
- **d2-precision** — precision-first, **single error tier**. No warn tier
  (~240 warnings on this repo would train authors to ignore the output) and no
  per-step suppression marker (every super-fr plan touching dispatch would need
  one).
- **d3-escape** — a `[manual]` phase is the escape route. The lint inspects
  agentic phases only, so the escape already exists and needs no code.
  Rejected: a spec-scope override in the shape of `skeleton-override-<slug>` —
  more machinery, and it would let an agentic phase keep a step the executor
  still cannot perform, which is the defect itself.
- **d4-tiers** — `claude-code/standard` rebound `claude-sonnet-5` →
  `claude-opus-5`; `hard` already `claude-opus-5`, `mechanical` already
  `claude-sonnet-5`. All three tiers bound, so no phase dispatch in this run
  can silently inherit the session model.

## 4. Design

### 4.A The lint — `fr.plan_ops.self_review`, error severity

A third detector beside `_MANUAL_VERB_RES`, in the same per-agentic-phase loop,
with the same exemptions:

- **agentic phases only** — `phase.phase.tag != "agentic"` → skip. This *is*
  decision d3's escape route.
- **ticked steps exempt** — `state == "x"` → skip, exactly as #252's second
  detector does. A ticked step already ran; the exemption keeps historical
  plans and step texts that merely *quote* the phrases from retro-erroring. At
  authoring time every step is unticked, so the gate bites where it should.

**Scanned text:** the step text with **fenced code blocks stripped**, inline
backticks **kept**. A fenced block is content being written, not an instruction
to the executor. Inline backticks must survive because the backticked agent
name *is* the object — stripping them turns ``Dispatch `blog-craft:post-researcher` per post``
into `Dispatch   per post` and the detector goes blind. (Measured: stripping
fences changes nothing for the head detector and removes one mechanism-token
false positive.)

**Two patterns, both error:**

1. **Imperative-head dispatch verb with an agent-shaped object.** The verb must
   open the step or follow a sentence boundary (optionally after a connective —
   `then`, `and`, `next`, `finally`, `also`), and an agent-shaped object must
   appear within ~60 characters on the same sentence:

   - verbs: `dispatch`, `delegate to`, `spawn`, `hand off to`, `fan out to`
     (with their inflections);
   - agent-shaped object: the words `agent`/`subagent`/`sub-agent`/`executor`/
     `researcher`/`reviewer`/`reader`, a backticked `` `plugin:name` ``
     reference, or a bare `plugin:name` whose name contains one of those words.

   The head anchor is what buys the precision: it separates *instructing* the
   executor to dispatch from *describing* dispatch, which is what 237 of the
   237 false positives were doing.

2. **Explicit mechanism tokens**, which name the machinery and cannot be
   describing an outcome: `subagent_type`, `Task tool`, `Agent tool`,
   `use the <X> agent`.

**Message** — names the cause, the reason it is unexecutable, and both ways out:

```
phase 3 (agentic) step P3.T1.S2 tells the phase executor to dispatch a
subagent (matched 'Dispatch `blog-craft:post-researcher`') — fr-phase-executor
has no Agent tool (OpenCode: task: deny) and cannot dispatch anything, so this
step is unexecutable by construction (#428). Name the OUTCOME instead ("gather
file:line-cited evidence following <protocol>"), or move the dispatch into a
[manual] phase.
```

**The precision claim is pinned in CI, not asserted.** A corpus test runs the
new detector over every agentic step of every plan folder under
`docs/superpowers/plans/` and `docs/superpowers/implemented/plans/` and asserts
**zero** hits — the 1,419-step measurement of §2.D, frozen, so that any future
widening of the patterns that would break super-fr's own plans fails in CI
instead of in an operator's run. Archived plans are read purely as a corpus;
nothing rewrites them.

That test needs one guard to be worth anything. Plans that do not parse must be
skipped (§2.D: 41 of them raise `PlanSchemaError`, 38 on a frozen `fr_version`
pin that will never be satisfied again), and "skip the unreadable, assert zero
hits on the rest" degrades **silently to a passing test that read nothing** the
day a schema bump makes every plan unparseable. So the test also asserts a
**floor on the number of plans it actually parsed** (≥ 30, against today's 43)
and on agentic steps scanned (≥ 1,000, against today's 1,419). A green corpus
test must mean the corpus was read — this repo's recurring defect is precisely
a check that reports success while doing nothing.

### 4.B The executor contract — refuse the tick (#428 item 2)

Today the honest executor reports the deviation **and ticks**. A tick is a
claim of performance; it must not be made for a step that could not be
performed as written.

- `plugins/super-fr/agents/fr-phase-executor.md` — a short section stating: you
  have **no** `Agent`/`task` tool; a step instructing you to dispatch,
  delegate, spawn or hand off to a subagent is a **BLOCKER**. Report it in your
  structured result, leave the step **unticked**, and do not complete the
  phase. Do not perform the work inline as a substitute — the dispatch existed
  to put that work in a context blind to yours.
- `plugins/super-fr/skills/fr-execute/SKILL.md` — the same contract beside the
  existing tick/skip commands (§ Procedure step 3 and § Constraints), since
  `fr-execute` is the skill an OpenCode/Hermes child loads.

Both are mirrored to OpenCode by `scripts/sync-opencode.py`, which regenerates
`.opencode/skills/fr-execute/SKILL.md` and the four
`.opencode/agent/fr-phase-executor{,-mechanical,-standard,-hard}.md` tier
variants. Drift is caught by `test_tripwire_opencode_skills_sync.py` for the
skill and `test_opencode_agent_mirror.py` for the agent variants — two
different guards, both must stay green.

### 4.C fr-plan guidance — where the error is born (#428 item 4)

A sibling bullet to **Pure agentic phases** in `plugins/super-fr/skills/fr-plan/SKILL.md`:
steps name **outcomes, not mechanisms**. "gather file:line-cited evidence
following `<protocol>`", never "dispatch `<agent>`". A step naming a tool rots
the moment the actor changes, and rots *silently*. Genuine orchestrator-level
dispatch goes in a `[manual]` phase (d3).

### 4.D Prose tokens pinned

`tests/unit/test_skill_tokens.py` already pins the load-bearing tokens of
fr-plan, fr-execute and fr-phase-executor (skeleton mandate, refactor contract,
handoff pointer). Three sibling tests pin this contract so a future edit that
drops it fails there rather than silently regressing.

### 4.E Release surfaces

- **Version: minor.** `packages/fr/src/**` and `plugins/super-fr/**` both
  change, and the change is a new mandatory gate — user-visible workflow
  behavior per `AGENTS.md`. `scripts/bump-version.py minor`.
- **Explainer.** A minor bump triggers `.claude/rules/explainers-currency.md`.
  `docs/explainers/01-fr-goal.md` already describes self-review catching
  "defects such as dependency cycles and manual work hidden inside an agentic
  phase" (line 364) — one sibling sentence there, then regenerate
  `01-fr-goal.html` with the `--isolated --no-project` incantation **from `/`**,
  verifying the unmodified re-render is byte-identical first.
- **No `parity.yaml` row.** This is a CLI lint every harness drives
  identically, not a per-harness enforcement surface; the parity tripwire pairs
  shipped *hook scripts* to rows, and no hook ships here.
- **No artifact shape change.** No model gains a field, so no stamp bump and no
  migration (`.claude/rules/artifact-versioning.md`).

## 5. Alternatives considered

- **#428's literal pattern list at error severity** — rejected on the
  measurement in §2.D: 237 false positives on this repo's own plans.
- **Two-tier severity (narrow=error, broad=warn)** — rejected (d2). ~240
  warnings per self-review run is noise that trains authors to ignore the
  output, and self-review's value is that its output is all signal.
- **Broad patterns plus a per-step suppression marker** (the
  `no-refactor-because:` shape) — rejected (d2). It pushes the cost onto every
  plan that legitimately discusses dispatch, i.e. most of super-fr's.
- **A spec-scope override decision** (`skeleton-override-<slug>` shape) —
  rejected (d3): it sanctions an agentic phase keeping a step the executor
  cannot perform.
- **A PreToolUse hook** — structurally impossible (§2.B). No call, nothing to
  intercept.
- **Granting the executor an `Agent` tool** — explicitly not considered a fix.
  A phase executor that can fan out is a different agent with different
  isolation semantics (that is `fr apply --to <runner>`'s job), and it would
  reopen #420's class of defect from the other side.

## 6. Test Plan

Unit, in CI — no live/post-merge verification is owed (this ships a lint and
prose; nothing deploys):

1. **Detector, true positives** — a synthetic plan whose agentic phase carries
   each of the six observed shapes (including the frank case verbatim,
   ``Dispatch `blog-craft:post-researcher` per post``) yields one `error`
   ReviewIssue per step.
2. **Detector, true negatives** — the five real super-fr step shapes from §2.D
   ("GREEN: implement `fr_dispatch.tick()` so it dispatches phases to the
   runner", "assert `fr apply --yes` refuses to dispatch…", "Dispatch phase 3
   to the vk runner via fr apply", …) yield no issue.
3. **Exemptions** — the same dispatch step in a `[manual]` phase yields
   nothing; a ticked (`x`) dispatch step in an agentic phase yields nothing.
4. **Fenced code is stripped, inline code is not** — a dispatch verb inside a
   ``` fence yields nothing; the backticked-agent form still errors.
5. **Corpus regression (§4.A)** — zero errors across every agentic step of
   every *parseable* plan folder in `docs/superpowers/plans/` and
   `docs/superpowers/implemented/plans/`, **plus** the floor assertions
   (≥ 30 plans parsed, ≥ 1,000 agentic steps scanned) that stop the test
   degrading into a green no-op.
6. **`fr plan self-review` exits 1** on a plan carrying a dispatch step, and
   the message names both escapes.
7. **Prose tokens** — `test_skill_tokens.py` asserts the executor contract in
   `fr-phase-executor.md` and `fr-execute/SKILL.md`, and the
   outcomes-not-mechanisms guidance in `fr-plan/SKILL.md`.
8. **OpenCode mirrors in sync** — `scripts/sync-opencode.py --check` clean
   (existing tripwires).
