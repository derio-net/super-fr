# Container git ownership — design

**Date:** 2026-09-26
**Slug:** `2026-09-26-container-git-ownership`
**Status:** design (fr-goal, autonomous)
**Repo:** `derio-net/super-fr` (single-repo change)
**Batch:** `container-git-ownership` — closes derio-net/super-fr#626

## 1. Goal

Inside a devcontainer, fr's own record commits (gh#610) must succeed. Today
they never do: the worktree is bind-mounted from the host, its files are owned
by the host uid, git refuses it as `dubious ownership`, and
`fr.artifacts.commit._classify_failure` reports a generic `GitRefusal`, so
`commit_records` prints `fr: not committed`. Loud and lossless (the write
survives), but the commit is never made.

### Non-goals

- No change to the refusal semantics for a *real* unsafe repo outside fr's own
  working tree: fr never widens git's trust beyond the directory it was asked
  to operate on.
- No wildcard `safe.directory = '*'`.
- `package-lists` (#650/#645) edits the same `POST_CREATE` and lands after this.

## 2. Background (verified against the code)

- `fr.git.git_answer` (`packages/fr/src/fr/git.py:107`) is the single seam every
  read/commit git call in `fr.artifacts.commit` goes through
  (`from fr.git import git_answer as _git`, `commit.py:57`), invoked with
  `cwd=root` and no `-c` config. `git_context` (`commit.py:264`) asks
  `rev-parse` first, so a dubious-ownership refusal poisons every later step.
- `commit.py:683` restores the index with a raw `subprocess.run(["git",
  "update-index", ...])` that bypasses `git_answer` — a second call site.
- Nothing under `fr/isolation`, `fr/record` or `fr/commands` sets
  `safe.directory`. `POST_CREATE` is `isolation/scaffold.py:426`; both committed
  profiles (`.devcontainer/dev|admin/devcontainer.json`) carry its rendered
  string as `postCreateCommand`.
- `git` honours `safe.directory` only from system/global/command-line config,
  never from the repo's own config — so `-c safe.directory=<path>` is valid and
  a repo-local setting would not be.

## 3. Design

Two ends of one root cause, each sufficient alone; both ship.

### A. fr's own git calls — works in containers that already exist

`git_answer` and the `update-index` restore pass `-c safe.directory=<root>`
where `<root>` is the resolved absolute `cwd` git is run in. Trust is scoped
to the one directory fr was pointed at. Because `git_context` asks from that
same `root` (which may be a subdirectory), the override also covers the
toplevel: `git_answer` is given the root the caller passed, and
`git_context`'s follow-up calls use the discovered `toplevel`, which — for a
worktree bind-mounted at its host path — is that directory or an ancestor the
caller already named. If a subdirectory `root` still trips the check, the
refusal remains loud (`GitRefusal`), never silent.

`-c` goes before the subcommand (`git -c safe.directory=… <args>`). The
helper builds the arg vector in one place so the two call sites cannot drift.

### B. The scaffold — new containers are right from the start

`POST_CREATE` gains `git config --global --add safe.directory "$PWD"`
(operator decision: workspace path, not `*`). A devcontainer's
`postCreateCommand` runs with the workspace folder as its cwd, and the
scaffold already mounts the workspace at its host path
(`scaffold.py:510`), so `$PWD` is exactly the worktree. Idempotent
(`--add` of an identical value is harmless; guarded with `|| true` like its
neighbours so a missing git never fails the container build).

Both committed profiles are regenerated by `fr init scaffold --force` so the
repo's own `.devcontainer/dev` and `.devcontainer/admin` match the scaffold —
the existing profile-drift tests pin this.

## 4. Debugging-first order

Bug, so red first: a unit test creates a real repo owned by a *different* uid
context — simulated by pointing `HOME`/`GIT_CONFIG_GLOBAL` at an empty config
and forcing git's ownership check with `GIT_TEST_ASSUME_DIFFERENT_OWNER=1`
(git's own test hook) — and asserts `commit_paths` commits. It fails on
`main` with the dubious-ownership `GitRefusal`, passes after A.

## 5. Risks

- **`GIT_TEST_ASSUME_DIFFERENT_OWNER` availability.** A git-version-specific
  test hook (added 2.35.2). Mitigation: the test skips with a reason on older
  git, and a second test asserts the argument vector directly so coverage
  survives.
- **Widening trust.** Bounded by construction: only the `cwd` fr was invoked
  in, never `*`, never persisted into config (`-c` is per-process).

## 6. Test Plan (automated; no post-merge step)

1. `commit_paths` commits under a forced foreign-owner environment (red on
   `main`, green after).
2. `git_answer` and the index-restore path both carry
   `-c safe.directory=<cwd>` before the subcommand.
3. `POST_CREATE` contains the `safe.directory "$PWD"` step, and the committed
   `dev` and `admin` profiles equal a fresh scaffold.

## Implementation Plans

One phase (bug fix, tightly coupled): tests first, then A, then B and profile
regeneration, then sync/docs checks.

## 7. Acceptance rows (born here; presented at spec review)

- `container-record-commits` — an fr record commit succeeds inside a
  devcontainer whose bind-mounted worktree git considers foreign-owned.
  Level: unit (forced foreign owner). Defense: it is the operator-visible
  claim of #626, not an implementation detail of `git_answer`.
- `scaffold-trusts-workspace` — a scaffolded profile trusts its own workspace
  path for git, so a fresh container needs no manual `safe.directory`.
  Level: unit (scaffold render). Defense: the user-visible half of the same fix.
